# OE1022D 命令验证协议

> **Human-in-the-Loop Protocol**
> 本协议要求操作员逐条确认设置命令。AI/脚本不会自动发送任何改变设备状态的命令。
> 禁止重置仪器、禁止启动扫频、禁止覆盖用户当前工作设置。

## Phase 1: Safe Query Phase（只读查询，无需人工确认）

> 本阶段所有命令均为查询，不会改变设备状态。脚本可自动执行。  
> 默认使用 **Ch-B**（通道参数 i=2）。

## Phase 2: Safe Set Phase（安全设置，需人工逐条确认）

> ⚠️ **重要**：执行本阶段前，操作员必须确认：
> 1. 当前 OE1022D 的设置可以被临时修改（不影响其他实验）
> 2. 设置完成后愿意手动恢复原有参数
> 3. 每条 setter 命令发送前，脚本会提示 `Execute? (y/n)`
> 4. **不要重置仪器**
> 5. **不要运行长时间采样**

| # | Command | Purpose | Expected Effect | Observed Response | Pass/Fail | Approved By | Timestamp | Human Notes |
|---|---------|---------|-----------------|-------------------|-----------|-------------|-----------|-------------|
| 1 | `FMODD 2,0` | Ch-B 设为外部参考 | 参考源 = External | | | | | |
| 2 | `RSLPD 2,0` | Ch-B 外部触发 = TTL 上升沿 | 触发方式 = TTL | | | | | |
| 3 | `PHASD 2,0` | Ch-B 相位设为 0° | 相位 = 0 | | | | | |
| 4 | `ISRCD 2,0` | Ch-B 输入源 = A (单端电压) | 输入 = A | | | | | |

---

## Forbidden Commands（本协议禁止发送）

以下命令在本次验证协议中**绝对禁止**发送：

| Command | 危险原因 |
|---------|----------|
| `SWRMD 2,1` | 启动内部扫频（可能打断当前测量） |
| `SWRMD 2,2` | 启动循环扫频 |
| `APHSD 2` | 自动相移（动作型指令，会改变相位且耗时） |
| 任何仪器复位命令 | 会丢失用户当前配置 |
| 长时间 `RALL?` 循环 | 非验证目的，属于采集行为 |

---

## 验证后恢复建议

若操作员修改了设备设置，建议在验证结束后手动恢复以下参数：
- 参考信号源 (`FMODD`)
- 触发方式 (`RSLPD`)
- 相位 (`PHASD`)
- 输入源 (`ISRCD`)

或记录修改前的原始值，验证结束后写回。
